# Поддержка пользовательского руководства

Единый исходник пользовательской документации — `help/index.html`. Он же публикуется отдельной HTML-страницей. Дублирующий документ Word/Markdown с тем же содержанием не создаётся, чтобы версии не расходились. Значок вопроса в общей шапке личного и семейного планов открывает `help/` в новой вкладке, сохраняя открытый план.

Страница не требует авторизации и не запрашивает базу. Все изображения лежат в `help/images/`; стили приложения подключаются относительно текущего репозитория. Поиск, увеличение скриншотов, печать/PDF и переключение темы дополняют обычную HTML-навигацию. Основной текст и ссылки доступны без JavaScript. Для PDF использовать кнопку «Печать / PDF» и системное сохранение в PDF.

## Что обновлять

1. После изменения поведения найти раздел по ID и обновить шаги, примеры и ограничения. Разделы: `start`, `navigation`, `settings`, `overview`, `income`, `categories`, `expenses`, `goals`, `gifts`, `debts`, `vacations`, `sick`, `plan-history`, `family`, `account`, `questions`, `terms`.
2. При изменении показанной карточки/таблицы заменить соответствующий JPEG в `help/images/`. Сохранять стабильное имя, чтобы ссылки не ломались. Проверить настоящий формат и размеры снимка; расширение должно соответствовать байтам файла. Обновить атрибуты width/height. Подписи и alt должны объяснять изображение, а не повторять имя файла.
3. Обновить дату в шапке руководства, проверить поиск по новому термину, якоря, мобильную компоновку и обе темы.
4. Выполнить `node --test tests/user-guide.test.mjs` и применимые тесты приложения. Проверить справку по кнопке вопроса из личного и семейного плана.

## Локальные вымышленные данные для снимков

Из корня репозитория в PowerShell:

```powershell
$env:FINANCE_GUIDE_PREVIEW = '1'
node tools/preview/family-server.mjs
```

Предпросмотр использует PGlite. Если модуль установлен отдельно, задать `FINANCE_PGLITE_MODULE` полным путём к его `dist/index.js`. Он создаёт только временную локальную базу, не подключается к Supabase и не отправляет письма. Переменная `FINANCE_GUIDE_PREVIEW` включает расширенные данные из `tools/preview/guide-data.mjs`: график, оклад, категории, этапы, долги, отпуск и больничный. Кнопки заполнения примером в приложении нет.

В напечатанном адресе `?user=a` — Анна, `?user=b` — Саша, `?user=c` — читатель. При запуске открывается собственный план; семейный выбирается в Настройках. Год примера — следующий относительно даты запуска; снимки текущей версии сделаны 02.11.2026 для плана 2027 года. Скриншоты сохранять средствами разрешённого браузерного инструмента. Начальная версия содержит снимки личного Обзора, Настроек, Доходов, Категорий, Расходов, целей, кредиток, рассрочек, отпуска, больничного, семейного Обзора и Доходов.

В режиме `FINANCE_GUIDE_PREVIEW=1` ответ публичного сервиса курсов подменяется вымышленными значениями (USD 100 ₽, EUR 110 ₽) на текущую дату; внешних запросов за курсом нет. Это относится только к локальному предпросмотру, рабочее приложение использует загрузку курсов.

05.11.2026 навигация накоплений объединена в «Цели» с вкладками «Копилки», «Подарки», «Подушки»: `goal-tabs.jpg` показывает новую навигацию, остальные снимки личного плана с верхним меню обновлены. История сохраняется в браузере; для чистого примера используйте новый локальный порт. Все финансовые записи и имена на снимках вымышлены.

16.11.2026 обновлены снимки модуля расходов. Для воспроизведения вместе с `FINANCE_GUIDE_PREVIEW=1` задать `FINANCE_TRACKING_GUIDE=1`. Ввести 3 500 ₽ и 700 ₽ в поля «Факт» у «Продуктов» и «Транспорта». Затем задать 5 000 ₽ в строке категории «Жизнь». Три поля выделятся рамками.

## Публикация

20.11.2026 добавлен `income-installment-override.jpg`. Для вымышленного примера вместе с `FINANCE_GUIDE_PREVIEW=1` задать `FINANCE_DEBT_GUIDE=1`. Открыть «Доходы» следующего года, развернуть «Подработку» 5 февраля и поставить 0 ₽ в поле платежа «Ноутбук». Проверить перенос 15 000 ₽ в зарплату той же даты, рамку ручного нуля, сохранение после перезагрузки и сброс на авторасчёт. После изменения движка снова собрать и развернуть `family-worker`.

07.11.2026 исправлена оценка доступности будущих выплат для подушек со сроком: плановые взносы более ранних этапов сохраняются отдельно от досрочной доливки, проверяется также собственный бюджет каждой подушки. Проверять перенос срока на дату прогноза, несколько сроков, маленькие будущие выплаты и сохранение взносов более ранних целей. Компоновка интерфейса не менялась, снимки не требуют замены. Пересобрать семейный обработчик перед выпуском.

06.11.2026 обновлены карточки Копилок и Подушек: вкладки, редактирование этапов в строке, прогнозы, окно операции с назначением и этапом. Обновить `goals.jpg`, `currency-goal.jpg`, `goal-operation.jpg` и `mobile-goals.jpg` из локального предпросмотра. Проверить покупку на цель, обычную трату, отмену через историю, мобильный экран и обе темы.

В тот же день возвращены скрытие прошедших записей, группировка по годам и прокрутка по три записи. Обновлены `goals.jpg`, `currency-goal.jpg`, `mobile-goals.jpg`, добавлен `goal-movements.jpg`. Локальный пример содержит прошлый этап, четыре будущих этапа (один без срока) и движения нескольких лет. Проверять год прогноза без срока, раскрытие истории, прокрутку четвёртой записи и появление сохранённой операции в прошлом.

06.11.2026 уточнены темп подушки и годовой свободный остаток. Проверять посильные взносы 3 000 ₽ при желаемых 5 000 ₽, неравные выплаты, несколько подушек, валюту и ручные ограничения. Исправление расчёта не меняет компоновку опубликованных скриншотов. Перед выпуском снова собрать `node tools/build-family-function.mjs` и обновить `family-worker`, чтобы сервер использовал тот же расчёт темпа, что приложение.

Дополнительно проверять случай с отрицательным балансом копилки и оплаченным прошлым этапом: деньги после темпа подушки должны распределяться дальше, а не удерживаться по уже пройденному сроку. Для тестов и документации используются только вымышленные примеры; реальные данные диагностики не сохраняются в файлы проекта.

06.11.2026 уточнено соблюдение очереди: адаптивный темп считается только на этапе Подушек, а доливка следует отдельным этапам Подарков, Копилок и Подушек. Проверять перестановку этапов, расходы между Копилками и Подушками, более ранний срок подушки ниже в очереди и посильный темп без повторного добора. Копилки и подушки могут накапливаться параллельно. Обновлены объяснения в руководстве и подсказки Подушек; компоновка карточек не менялась.

06.11.2026 исправлено закрытие этапа в дату необеспеченной покупки. Проверять покупку до, в день и после срока, частичное погашение долга, независимость этапов, историю баланса и ручной снимок закрытия. Покупки учитываются последовательно без переигрывания прошлых строк. В расчётных снимках `purchaseDebt` хранит необеспеченную часть покупки. Компоновка не менялась; для руководства используется вымышленный пример 100 000 ₽ при накопленных 90 000 ₽. Пересобрать семейный обработчик перед выпуском; новая миграция для этого исправления не требуется.

Перед публикацией выполнить `supabase/migrations/20261106100556_goal_spending_purpose.sql` для существующей базы. Старые движения получают `purpose='other'`. Для чистого проекта использовать собранный `v2/install.sql`. Обновить `family-worker` вместе с подготовленным общим движком из `supabase/functions/_shared/finance`, чтобы прогноз семейных взносов использовал те же правила покупок.

Опубликовать `help/` вместе с обновлённым `src/` обычным релизом GitHub Pages после миграции. Корень `help/` содержит `index.html`, поэтому ссылка работает и при размещении проекта в `/имя-репозитория/`. Не копировать в публичную документацию служебные данные предпросмотра или реальные данные аккаунтов.
