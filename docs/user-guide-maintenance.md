# Поддержка пользовательского руководства

Единый исходник пользовательской документации — `help/index.html`. Он же публикуется отдельной HTML-страницей. Дублирующий документ Word/Markdown с тем же содержанием не создаётся, чтобы версии не расходились. Значок вопроса в общей шапке личного и семейного планов открывает `help/` в новой вкладке, сохраняя открытый план.

Страница не требует авторизации и не запрашивает базу. Все изображения лежат в `help/images/`; стили приложения подключаются относительно текущего репозитория. Поиск, увеличение скриншотов, печать/PDF и переключение темы дополняют обычную HTML-навигацию. Основной текст и ссылки доступны без JavaScript. Для PDF использовать кнопку «Печать / PDF» и системное сохранение в PDF.

## Что обновлять

1. После изменения поведения найти раздел по ID и обновить шаги, примеры и ограничения. Разделы: `start`, `navigation`, `settings`, `overview`, `income`, `categories`, `expenses`, `goals`, `gifts`, `debts`, `vacations`, `sick`, `plan-history`, `family`, `account`, `questions`, `terms`.
2. При изменении показанной карточки/таблицы заменить соответствующий JPEG в `help/images/`. Сохранять стабильное имя, чтобы ссылки не ломались. Проверить настоящий формат и размеры снимка; расширение должно соответствовать байтам файла. Обновить атрибуты width/height. Подписи и alt должны объяснять изображение, а не повторять имя файла.
3. Обновить дату в шапке руководства, проверить поиск по новому термину, якоря, мобильную компоновку и обе темы.
4. Выполнить `node --test tests/user-guide.test.mjs` и применимые тесты приложения. Проверить справку по кнопке вопроса из личного и семейного плана.

## Локальные вымышленные данные для снимков

Из корня репозитория в PowerShell:

```powershell
$env:FINANCE_GUIDE_PREVIEW = '1'
node tools/preview/family-server.mjs
```

Предпросмотр использует PGlite. Если модуль установлен отдельно, задать `FINANCE_PGLITE_MODULE` полным путём к его `dist/index.js`. Он создаёт только временную локальную базу, не подключается к Supabase и не отправляет письма. Переменная `FINANCE_GUIDE_PREVIEW` включает расширенные данные из `tools/preview/guide-data.mjs`: график, оклад, категории, этапы, долги, отпуск и больничный. Кнопки заполнения примером в приложении нет.

В напечатанном адресе `?user=a` — Анна, `?user=b` — Саша, `?user=c` — читатель. При запуске открывается собственный план; семейный выбирается в Настройках. Год примера — следующий относительно даты запуска; снимки текущей версии сделаны 02.11.2026 для плана 2027 года. Скриншоты сохранять средствами разрешённого браузерного инструмента. Начальная версия содержит снимки личного Обзора, Настроек, Доходов, Категорий, Расходов, целей, кредиток, рассрочек, отпуска, больничного, семейного Обзора и Доходов.

04.11.2026 добавлен `currency-goal.jpg` с долларовой копилкой. В режиме `FINANCE_GUIDE_PREVIEW=1` ответ публичного сервиса курсов подменяется вымышленными значениями (USD 100 ₽, EUR 110 ₽) на текущую дату; внешних запросов за курсом нет. Это относится только к локальному предпросмотру, рабочее приложение использует загрузку курсов.

05.11.2026 навигация накоплений объединена в «Цели» с вкладками «Копилки», «Подарки», «Подушки»: `goal-tabs.jpg` показывает новую навигацию, остальные снимки личного плана с верхним меню обновлены. История перенесена в раскрываемый блок Настроек. `forecast-explanation.jpg` показывает уведомление на 3 секунды, `plan-history.jpg` — историю в Настройках; успешная отмена удаляет запись, ошибка сохраняет её для повторной попытки. Проверены переход по уведомлению, сохранение активного ввода при его исчезновении и мобильное меню при ширине 390 px. История сохраняется в браузере; для чистого примера используйте новый локальный порт. Все финансовые записи и имена на снимках вымышлены.

## Публикация

Опубликовать `help/` вместе с обновлёнными `src/ui/app.js` и `src/ui/styles.css` обычным релизом GitHub Pages. Корень `help/` содержит `index.html`, поэтому ссылка работает и при размещении проекта в `/имя-репозитория/`. SQL, Edge Functions и секреты для этого обновления не требуются. Не копировать в публичную документацию служебные данные предпросмотра или реальные данные аккаунтов.
