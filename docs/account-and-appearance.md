# Удаление аккаунта и тема оформления

## Как пользоваться

В настройках личного и семейного плана появился раскрывающийся блок **«Оформление»**. В нём можно выбрать светлую, тёмную тему или **«Как в системе»**. Выбор применяется сразу и сохраняется в этом браузере для всех планов. Системный режим следует настройке устройства, включая её изменение при открытом приложении. Перед загрузкой интерфейса сохранённая явная тема применяется в HTML, чтобы при обновлении не показывать сначала другую тему.

Действие **«Удалить аккаунт»** находится в **«Настройки → Вход и безопасность»**, рядом с выходом из аккаунта. Окно сначала запрашивает актуальный список затрагиваемых планов и показывает последствия:

- Личные планы без других участников удаляются вместе с данными.
- Общие планы остаются другим участникам; доступ удаляемого пользователя прекращается. Если пользователь был единственным владельцем, удаление блокируется до назначения другого владельца. В этом же окне можно выбрать существующего участника и явно подтвердить назначение; старый владелец сохраняет свою роль до удаления аккаунта. Назначение нового владельца сохраняется и при отмене последующего удаления.
- Участие в семье и будущие отчисления прекращаются. Проведённые взносы и общая история сохраняются, профиль обезличивается. Личные правила, ручные будущие взносы и внутренний расчётный журнал удаляются. Исторический вычет семейных взносов из сохраняемого общего источника остаётся прежним.
- Последняя семья удаляется из доступа с отдельным предупреждением, как при уходе последнего участника. Техническая история проведённых взносов сохраняется.
- Удаляется учётная запись Supabase Auth, её сессии и личные настройки. Интерфейс очищает локальную сессию и возвращает на вход. При следующем открытии приложения проверяется действующий пользователь Auth, а не только наличие сохранённого JWT.

Для окончательного подтверждения пользователь вводит **УДАЛИТЬ**. Запрос удаляет только текущего авторизованного пользователя: передать чужой ID в него нельзя. Сервер повторно проверяет состав и роли участников. Если они изменились после открытия окна, нужно заново посмотреть условия и подтвердить удаление. Ошибка на любом шаге удаления откатывает всю транзакцию.

## Применение обновления

Для существующей базы, где уже применена семейная миграция, в **Supabase → SQL Editor → New query** вставить полное содержимое файла:

`supabase/migrations/20261031204207_voluntary_account_deletion.sql`

Нажать **Run**, затем опубликовать обновлённые статические файлы сайта. Дополнительная Edge Function, её повторная сборка или новые секреты для этих изменений не требуются. Удалённые аккаунты и базы агентом не изменялись.

Для чистой базы обновлённый `v2/install.sql` уже включает эту миграцию. Не использовать скрипт сброса данных. Общий установщик пересобирается командой `node tools/build-install.mjs`.

Удаление Auth выполняется в закрытой серверной SQL-функции вместе с очисткой данных, без service role в браузере. Прямое удаление пользователя из `auth.users` поддерживается Supabase; остающиеся до истечения JWT учитываются проверками наличия пользователя и удалением всех его участий. Источник: [Supabase User Management](https://supabase.com/docs/guides/auth/managing-user-data).

## Проверка

- `node --test tests/*.test.mjs` — интерфейс, настройки тем, подтверждение удаления, защита от повторного клика, обновление условий и обработка сетевых ошибок.
- `node --test tests/account.database.mjs` — настоящие SQL-запросы в локальном PostgreSQL/PGlite: права, назначение владельца, конфликты состава, полный откат при поздней ошибке, удаление личных данных и сохранение обезличенной общей истории.
- `node --test tests/family.database.mjs` — совместимость семейного расчёта и чистая установка.

Для SQL-тестов нужен `@electric-sql/pglite@0.5.14`; путь к его `dist/index.js` можно указать через `FINANCE_PGLITE_MODULE`. Тесты не подключаются к рабочей базе.
