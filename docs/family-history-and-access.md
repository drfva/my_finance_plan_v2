# История и доступ участников

Журнал семейных изменений хранит записи за скользящий месяц от текущего момента по времени Москвы: например, 15 ноября остаются записи с 15 октября. Более старые записи удаляются из `family_audit`. Проведённые взносы, их распределения и бюджеты прошлых месяцев сохраняются.

История выдаётся сервером по 10 записей, сначала последние. Есть номера страниц, «Назад», «Вперёд» и «Обновить». Открытый просмотр закрепляет верхний идентификатор: новые события не сдвигают уже открытые страницы. «Обновить» начинает с последних записей. При истечении срока хранения последняя страница может сокращаться; сервер корректирует номер страницы.

Автоматическая очистка выполняется отдельной задачей Cron каждый час на 17-й минуте, если `pg_cron` уже включён. Очистка также встроена в существующую серверную обработку семейного worker, в команды семьи и загрузку страниц истории. Истёкшие записи отфильтровываются при любом чтении, даже до очередной физической очистки. При отсутствии Cron рекомендуется включить его по существующей инструкции запуска семейного плана.

Все действующие участники семьи видят одинаковые взносы и распределения друг друга, в том числе нулевые прогнозы. Приглашённый участник получает тот же общий доступ, что и создатель. Сумму и распределение будущего взноса редактирует только его автор; чужая карточка доступна для просмотра, прошедшая защищена от правок. Общими категориями и расходами участники по-прежнему управляют совместно. Личные доходы и правила взносов других участников не раскрываются.

В Доходах последняя прошедшая карточка каждого участника видна сразу. Более ранние записи доступны через «Показать предыдущие взносы». Это предотвращает ситуацию, когда последняя карточка одного участника скрывала прошедшие взносы остальных.

## Другие изменения интерфейса

У шапок таблиц оставлены только верхние скругления. Убрана оставшаяся подсказка о плане и факте в обзоре расходов. В Копилках и Подушках вместо списка валют — кнопка с текущим знаком валюты и палитра доступных валют. Выбор сохраняет то же поведение изменения валюты, что и прежний список.

## Публикация

В SQL Editor обеих используемых баз выполнить `supabase/migrations/20261101190301_family_history_and_access.sql` после предыдущих миграций семейного бюджета. Затем опубликовать файлы сайта. На чистой базе использовать обновлённый `v2/install.sql`. Сигнатуры существующего worker не менялись.

Если предыдущая попытка завершилась ошибкой «Не удалось обновить семейную историю», заново скопировать весь исправленный файл миграции в новый запрос SQL Editor и выполнить целиком. Причина исправлена: сопоставление фрагмента старой функции больше не зависит от переносов строк Windows при вставке. Ошибочная попытка откатывалась целиком; повторный запуск исправленного файла также поддерживается после успешного выполнения.

Миграция сразу удаляет журнал старше месяца и настраивает последующую очистку. Внутренние функции очистки и выборки закрыты для прямого вызова клиентом; публичный RPC страницы проверяет участие в запрашиваемой семье. Прямой доступ к таблицам и RLS сохраняются.

Проверки: `node --test tests/*.test.mjs`, `node --test tests/family-access-history.database.mjs`. SQL-проверки используют локальный PGlite; при необходимости путь задаётся в `FINANCE_PGLITE_MODULE`.
