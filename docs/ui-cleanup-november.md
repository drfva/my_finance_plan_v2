# Упрощение экранов и навигации

- Ошибка проверки входа или загрузки плана показывает обычный экран с кнопкой «Повторить». Ответ сервера, адрес базы и инструкции SQL не выводятся.
- Кнопки мастера первого входа открывают нужный раздел и прокручивают его под закреплённую шапку, включая «Оклад» и «Налог».
- В шапке убрана метка типа плана. В настройках сокращены указанные тексты, переименованы «Источник взносов» и «История доходов», убрана отдельная кнопка открытия семьи.
- Каждый год графика выплат сворачивается независимо. Количество выплат и быстрые действия доступны без раскрытия; добавление выплаты раскрывает её год.
- В календаре есть быстрый выбор месяца и года. Для рабочего дня показывается «Сделать нерабочим», для нерабочего — «Сделать рабочим». Свой день можно вернуть к общему календарю.
- Рабочие дни для расчёта оклада берутся из календаря с учётом личных изменений отдельных дат. Старые месячные `working_day_overrides` остаются в сохранённых данных для совместимости, но больше не влияют на расчёт. Зафиксированные выплаты сохраняют свои суммы.
- Почта и кнопка её смены выровнены по центру; удаление аккаунта выделено красной кнопкой.
- Отпуска и больничные фильтруются по году начала. Период с декабря по январь относится только к декабрьскому году. В фильтре доступны также годы записей вне графика выплат. История прошедших периодов по-прежнему сворачивается.
- Настройка досрочного погашения карт перенесена из «Кредитов» в конец раздела «Порядок распределения выплаты».
- В копилках и подушках «Закрыть цель» оформлено как второстепенное действие. Новый этап или движение автоматически раскрывает свой список и прокручивает его к новой строке; это работает и для траты, созданной из этапа.
- В доходах дата фактического поступления отпускных находится рядом с их суммой в поле дохода. Дублирующая строка и указанные подсказки удалены; действия распределения выровнены справа.
- «Категории» оформлены раскрывающимся списком: в сводке видны название, сумма или доля, количество статей, способ распределения и сезон. Название, режим, сумма, статьи и сезон редактируются внутри. Категории раскрываются независимо, новая категория или статья сразу открывается и получает фокус. Суммы из статей и процентные доли пересчитываются при правках; права читателя сохранены.

## Публикация

Миграция SQL не требуется. Опубликовать обновлённые файлы сайта.

Календарь используется и серверным семейным расчётом: чтобы сайт и сервер считали одинаково, переопубликовать `family-worker`. Общие модули уже подготовлены командой `node tools/build-family-function.mjs`; она повторяется перед деплоем, если исходники изменились снова.

Из корня проекта с авторизованным Supabase CLI:

```sh
supabase functions deploy family-worker --project-ref PROJECT_REF --use-api
```

`PROJECT_REF` — идентификатор той базы, к которой подключено публикуемое приложение.

## Проверка

`node --test tests/*.test.mjs` — 208 тестов. Дополнительно в локальном браузере на вымышленных данных проверены переходы к окладу и налогу, прокрутка длинного списка этапов, независимое раскрытие годов, быстрый выбор календаря, изменение рабочего дня, центрирование кнопки почты и цвет удаления аккаунта. Для категорий проверены создание с фокусом в названии, добавление и редактирование статей, пересчёт общей суммы, процентная категория, сворачивание и сохранение после перезагрузки.
