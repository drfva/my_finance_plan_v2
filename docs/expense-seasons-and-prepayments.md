# Сезонные суммы, досрочное погашение и компоновка

## Суммы по сезонам

В категории без статей и в каждой статье можно задать несколько ежегодных сезонов с отдельной суммой на месяц. Вне них действует основная сумма. Чтобы тратить только в заданные сезоны, основную сумму ставят 0. Если у категории есть статьи, сумма категории складывается из них: сезонные суммы задаются в статьях.

Кнопка «+ сезон с суммой» открывает поля «Сезон с», «По», «Сумма в месяц». Даты — ММ-ДД. Границы включены, сезон может переходить через Новый год, например 12-01 — 03-20. Сезоны одной строки не должны пересекаться; несуществующие даты вроде 11-31 отклоняются. 02-29 допустимо для високосных лет.

Изменения вступают в расчёт после «Применить». Отмена оставляет сохранённые данные прежними. Проверки выполняются и в браузере, и в базе. Старый одиночный сезон назван «Период действия» и сохранён как ограничение применимости: вне него строка не учитывается, внутри действуют основная сумма и сезонные суммы. Чтобы новые сезонные суммы действовали за пределами старого периода, его нужно расширить или убрать. Данные старых сезонов не переписываются. Поля периода действия теперь растянуты на ширину блока.

Суммы фиксированных категорий, автоматическое распределение по выплатам и план статей в Расходах используют актуальные сезонные значения. Процентные категории используют непосредственно заданный процент выплаты, без суммы на месяц и денежных сезонов. Их период действия ограничивает даты выплат. Ручные суммы отдельных выплат продолжают применяться поверх шаблона.

## Досрочное погашение

В «Настройки → Порядок распределения выплаты» находятся настройки кредиток и рассрочек. Досрочное погашение использует **свободный остаток после всех обычных распределений**, включая семейный взнос и доливку целей. Для кредиток прежний режим сохранён; для рассрочек досрочное погашение по умолчанию выключено. Очередь кредиток и рассрочек определяется порядком их этапов.

При включении рассрочки получают свободный остаток в счёт ближайших будущих частей. Следующие выплаты оплачивают только непогашенную часть. Нельзя досрочно уменьшить платёж, уже закреплённый в другой выплате. Сумма платежей по договору хранится отдельно от досрочных отчислений: в графике показываются сумма досрочного погашения и остаток к дате части.

При фиксации выплаты сохраняется снимок оплаченных частей. Он переживает перезагрузку, выключение правила и пересоздание идентификаторов графика. Миграция закрепляет существующие платежи зафиксированных выплат по прежней схеме. Проведение семейного взноса сервером сохраняет этот снимок атомарно с выплатой.

## Компоновка

- В Доходах кнопки в заголовках блоков собраны вертикально и согласованы с названием блока.
- В Расходах убрана подсказка о плане и отклонении 5%; сама подсветка отклонений сохранена.
- Нажатие на название месяца производственного календаря открывает выбор года и сетку из 12 месяцев. Выбор месяца закрывает пикер; Escape также закрывает его. Выбор дня и действие «Сделать рабочим/нерабочим» занимают компактную строку.

## Установка обновления

Сначала применить к каждой используемой базе полный файл:

`supabase/migrations/20261031234538_expense_seasons_and_installment_prepayments.sql`

Это можно сделать в Supabase → SQL Editor → New query → Run. Повторный запуск безопасен. Затем опубликовать статические файлы сайта.

Обновился общий расчётный движок. Пакет Edge Function пересобран командой `node tools/build-family-function.mjs`; нужно переопубликовать его для соответствующего проекта:

```sh
supabase functions deploy family-worker --project-ref PROJECT_REF --use-api
```

Общий установщик `v2/install.sql` также пересобран и включает новую миграцию. Для действующей базы используется отдельная миграция, а не установщик чистой базы.

## Проверка

- `node --test tests/*.test.mjs` — 219 тестов: сезоны, расходы, прогнозы, досрочное погашение, сохранение снимков, порядок этапов, сохранение денег и интерфейс.
- `node --test tests/expense-debts.database.mjs` — 5 тестов на настоящем локальном PostgreSQL/PGlite: миграция существующих и защищённых семейных выплат, повторный запуск, проверки JSON, права доступа, сохранение через API, семейный worker и защита от повторного проведения.
- `node --test tests/family.database.mjs` — семейные расчёты, чистая установка и Cron.

В браузере проверены две сезонные суммы и их сохранение после перезагрузки, одинаковая ширина полей периода, выбор года и високосного февраля в пикере, компактный блок дня и вертикальные кнопки в Доходах. База проверяется локально, рабочие данные не изменяются. Тип JSONB и ограничения CHECK используются согласно [документации Supabase](https://supabase.com/docs/guides/database/json).
