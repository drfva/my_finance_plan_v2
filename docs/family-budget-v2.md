# Семейный бюджет: годы, категории и распределение взносов

Обновление по запросу от 01.11.2026. Месячный бюджет рассчитывается от всех полученных и ожидаемых взносов месяца. Фиксированная сумма делится между взносами пропорционально их суммам. Распределения проведённых взносов сохраняются; перерасчёт затрагивает будущие карточки.

## Категории

Раздел оформлен раскрывающимися карточками, как в личном плане. Два режима: «Фиксированная сумма в месяц» и «Фиксированный процент в месяц». Правило действует ежемесячно, начиная с месяца создания категории. У процентной категории сумма за месяц равна сумме полученных и ожидаемых взносов × процент / 100.

Подкатегории используют режим родителя. Их суммы либо проценты складываются в итог категории, общий итог недоступен для ручного ввода. Можно задать период действия ММ-ДД с переходом через Новый год, а для фиксированной суммы — несколько непересекающихся сезонов с отдельными суммами. При изменениях сезона в пределах одного месяца учитываются значения на даты взносов; фиксированный бюджет определяется с весами сумм взносов. Для месяца без взносов используется значение на 15-е число. Изменение денежной суммы не стирает сохранённый процент и наоборот.

Изменение шаблона в середине месяца задаёт новый общий план месяца. Уже распределенные суммы засчитываются. Если новый план меньше закреплённого распределения, прошлое не уменьшается, новых автоматических отчислений в эту категорию нет. При добавлении подкатегорий ранее закреплённая сумма родителя также засчитывается. Превышение уже потраченной суммой одной подкатегории её нового плана засчитывается в общий бюджет родителя.

Удаление категории убирает её и подкатегории из будущего распределения. Исторические распределения, названия в проведённых карточках и внесённые факты сохраняются. Возврат категории из архива в этом обновлении не добавлялся.

## Доходы и Обзор

В Доходах показаны карточки всех взносов выбранного года с цветами участников. Есть «Все участники», «Мои взносы» и отдельный выбор каждого участника, включая вышедших с историей взносов. Сумму будущего взноса может менять только его автор; общее распределение будущего взноса может менять любой действующий владелец семейного бюджета.

Внутри карточки видны категории, подкатегории, суммы, общий расход и остаток. Ручная сумма выделена рамкой и сохраняется при обновлении прогноза; «Подставить по шаблону» удаляет ручные значения распределения только этой карточки. Прошедшие карточки доступны для просмотра. Прежние взносы сворачиваются, при раскрытии сохраняется фокус у ближайшего предыдущего.

Обзор показывает полученные взносы, ожидаемые взносы и план расходов за год, таблицу поступлений каждого участника и бюджет всех 12 месяцев с годовым итогом. Фиксированные расходы учитываются и в месяцах без взносов: такой план отображается как нераспределённый, дефицит виден явно. Статистический факт не меняет план и размер взносов. Между месяцами нет автоматического переноса остатка.

Общие вкладки используют годовую навигацию с окном до трёх соседних годов. В Расходах внутри выбранного года остаётся выбор месяца, как в личном плане.

Годы появляются по датам взносов и сохраняются в семейном плане: удаление последнего прогноза года не удаляет фиксированный бюджет этого года.

## Сохранение и приватность

Единый расчёт находится в `family_api.budget_plan`: API возвращает готовое распределение для браузера, эта же функция используется сервером для фиксации. Наличие приложения на экране не требуется: существующий ежечасный worker закрепляет распределение одновременно с проведением взноса. Неподтверждённые взносы остаются прогнозом.

Снимок проведённого взноса хранится в `family_contributions.allocation_snapshot` и защищён триггером. Закрытые месяцы хранят свои месячные цели в `family_budget_months`. Ручные будущие суммы хранятся в `family_allocation_overrides` по участнику, исходной выплате и категории: смена идентификатора прогноза при обновлении worker не стирает их. Команды сохраняют проверки участия, версии и идентификатора запроса.

Новые таблицы имеют RLS и закрыты для прямого чтения и записи через REST. В семейный ответ не добавлены личные доходы, свободные остатки, источники и правила взносов других участников. Внутренний расчёт и функции фиксации напрямую недоступны `authenticated`, `anon` и `service_role`: их вызывают существующие защищённые RPC.

Старые помесячные суммы остаются исключениями соответствующих месяцев. Последняя известная сумма категории становится шаблоном следующих месяцев. Правка нового шаблона удаляет старые исключения для текущего и будущих месяцев этой категории; закрытые месяцы и проведённые распределения сохраняются.

## Публикация

1. В SQL Editor тестовой базы выполнить `supabase/migrations/20261101130135_family_monthly_budget.sql`. В нём нет сброса личных данных; предыдущие миграции должны быть установлены.
2. Опубликовать обновлённые файлы сайта и проверить тестовый план.
3. Повторить миграцию и публикацию для основной базы/сайта.

Сигнатуры worker RPC не менялись: уже опубликованный `family-worker` совместим с миграцией и вызывает фиксацию в той же транзакции. Общие модули функции подготовлены заново; при очередном развёртывании использовать обычные команды:

```sh
node tools/build-family-function.mjs
supabase functions deploy family-worker --project-ref PROJECT_REF --use-api
```

Для полностью чистой базы обновлён `v2/install.sql`; на существующей базе выполняется только новая миграция.

Проверки: `node --test tests/*.test.mjs`, `node --test tests/family-budget.database.mjs`. SQL-проверки требуют PGlite; локальный путь пакета можно передать в `FINANCE_PGLITE_MODULE`.
