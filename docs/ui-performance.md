# Расчёт и отложенное сохранение

`ui/plan-cache.js` хранит один результат доходов и распределения для текущего состояния, объекта config и сегодняшней даты. Меню, раскрытие карточек, фокус и черновики используют тот же результат. Store сбрасывает config при изменении доменов, настроек, загрузке другого плана и принятии серверных таблиц. При добавлении новых путей изменения финансовых данных необходимо сохранять эту инвалидацию. Изменение текущего дня также обновляет результат. Предупреждения о сроках привязаны к результату симуляции.

`applyEdit` различает изменённое, прежнее и невалидное значение. Повтор значения не создаёт ручной override и не закрепляет автоматически созданный этап. Store дополнительно проверяет, действительно ли изменился домен, до события change и постановки сохранения в очередь.

Поля data-edit, data-setting и data-account-title вызывают beginEditing/endEditing. Store объединяет накопленные правки домена, пока его поле находится в фокусе, затем использует обычную задержку 500 мс. Явные save/flush, смена плана и уход со страницы отправляют уже принятые изменения независимо от фокуса. Не завершённый ввод даты не записывается: событие change фиксирует выбранную дату, а Safari input без change обрабатывается при выходе из поля. Сброс отдельной кнопкой остаётся явным действием.

Ответ сохранения может добавить значения по умолчанию. Если в этот момент пользователь вводит данные, оболочка откладывает замену DOM до выхода из поля, чтобы не потерять ввод. Фоновое обновление семейного прогноза также ждёт завершения ввода; если ответ пришёл после появления новых локальных правок, он не заменяет их снимком сервера. Конфликты версий и ошибки продолжают обрабатываться штатно. Изменения не затрагивают SQL, RPC-контракты или права доступа.

Проверки: отсутствие таймеров/событий/запросов для прежнего значения; объединение правок и принудительный flush; 30 чтений неизменного плана с одной симуляцией; инвалидация при изменениях, загрузке и смене даты; сравнение с полным расчётом; локальный PGlite-предпросмотр для календаря, этапа и повторной загрузки сохранённых значений.
