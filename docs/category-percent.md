# Процентные категории

В режиме «Процент от выплаты на руки» задаётся `percent_value` от 0 до 100, в том числе дробный. Для каждой выплаты сумма равна её доходу × процент / 100 с обычным округлением плана. Например, 10 % от 50 000 ₽ — 5 000 ₽. Другие категории, их суммы и статьи не меняют процент.

База по умолчанию — полная выплата на руки с её отпускными и больничным. Явная настройка этапа категорий `percent_base: gross` сохраняет расчёт от начисленного. Разовые выплаты также участвуют. Вне периода действия категории автоматическая сумма равна нулю.

В процентном режиме сумма месяца, статьи и сезоны с денежными суммами не вводятся. Сохранённые ранее данные остаются для обратного переключения на фиксированный режим, но не используются в расчёте процента. Уже внесённые факты по статьям остаются видны в Расходах. Процент берётся из существующего поля `percent_value`; если там 0, нужно задать желаемый процент. Автоматического восстановления процента из старых сумм нет.

Ручная правка суммы категории в отдельной выплате имеет приоритет. Проверка за месяц сравнивает внесённые суммы с суммой рассчитанных процентов, а не со старым денежным планом. При изменении доходов или процента расчёт обновляется без отдельного сохранённого кэша.

«Распределить выплату» сначала рассчитывает процентные категории, затем делит оставшийся доход между активными фиксированными категориями пропорционально их суммам. Если фиксированных категорий нет, остаток остаётся свободным. Проценты не нормализуются до 100 %; превышение бюджета отражается обычным дефицитом.

## Публикация

Новая миграция SQL не нужна: `percent_value` и его ограничение уже есть в схеме. Опубликовать файлы сайта и обновить `family-worker`, поскольку семейный сервер использует тот же личный расчёт расходов:

```sh
node tools/build-family-function.mjs
supabase functions deploy family-worker --project-ref PROJECT_REF --use-api
```
